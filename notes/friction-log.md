# Friction log (raw, while building; becomes arkiv/friction.md)

- 2026-10-17 11:40 IST. `predictEntityKeys` lives on the public client, not the wallet client, although it exists to build a wallet's batch. TS2339 "Property 'predictEntityKeys' does not exist" on the wallet client. SDK 0.8.1.
- 2026-10-17 11:20 IST. Node 25 ExperimentalWarning "localStorage is not available because --localstorage-file was not provided" on every script run (also seen in spike).
- 2026-10-17 11:30 IST. SDK 0.8.1 runs unchanged in a Cloudflare Worker (nodejs_compat), including executeBatch and sendTransaction. Worked first time (tested path).
- 2026-10-17 13:45 IST. Anonymous RPC: arkiv_query returned HTTP 429 with `ratelimit: limit=10000, remaining=0, reset=2655` and `retry-after: 2655` (about 44 min) after roughly 100 queries from one IP in a few minutes (a 40-query probe plus a page refreshing 8 queries every 30 s). eth_blockNumber on the same IP still showed `limit=600, remaining=599, reset=60`, so there are two buckets: a request-rate bucket and a cost bucket. The access-keys doc says "the public RPC works without one, at the default rate limit" but gives no numbers, and the SDK surfaces it as a generic HTTP error. Expected: documented anonymous quota and cost per query; the SDK exposing Arkiv-Cost / Arkiv-Quota-Used-Percent.
- 2026-10-17 14:40 IST. `predictEntityKeys` is an `eth_call` to `0x4400000000000000000000000000000000000044` `entityNonce(address)`, not an `arkiv_*` method. Our read-only relay allowlisted arkiv_* and a few eth_* methods and blocked it ("read methods only"). Nothing in the docs says which RPC methods the SDK needs for each action, which matters for anyone putting a proxy or access-key relay in front of the RPC.
